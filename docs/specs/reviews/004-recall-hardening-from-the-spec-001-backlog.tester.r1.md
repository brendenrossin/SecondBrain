## Tester review — 004
Verdict: approve with changes

Coverage: 13 goals, 31 scenarios, uncovered goals: none. Goals 1, 3 and 12 are covered only by scenarios that a broken implementation can pass or that can't be run as written. The blockers below cover those three.

- [x] **BLOCKER** Goal 1's regression net points at things that don't exist. `tests/fixtures/recall/goldens.json` only holds unfiltered `retrieve(q, top_k=10)` output at the default 0.3 floor, plus raw store searches. There is no "stored recall goldens" for endpoint hits, and no golden for `retrieve(..., include_folders=["Witt"])`. The session fixture also has no lexical-only Witt chunk: all 7 Witt notes carry `sim` ≥ 0.55, above the 0.40 floor. So "Given a fixture index where the query has 3 lexical-only Witt chunks and 4 vector hits" can't use that index. — Broken impl that passes: `retrieve_vector_led` drops the lexical contribution to RRF, or returns `len(lexical_results)` as the count. With no golden and no overlapping lexical/vector ids, nothing fails. — Scenario to add: name a new `_build` fixture with 4 notes at sim ≥ 0.40, at least one of which also matches lexically, plus 3 notes at sim < 0.40 that match the query term. Before any `src/` change, capture new golden keys in `capture_goldens.py`: (a) recall endpoint hits (note_path, chunk_id, score, similarity) for `TEST_QUERY` and that fixture's query, with and without each filter; (b) `retrieve(q, top_k=k_vec+K_LEX, include_folders=["Witt"])` at min_similarity 0.40. Add test `test_vector_led_matches_retrieve_minus_keyword_only`. On the same retriever it asserts: `{c.chunk_id: c.rrf_score for c in vector_led} == {same for c in retrieve if c.similarity_score > 0}`, and `skipped == sum(c.similarity_score == 0 for c in retrieve)`. — resolved: recall_goldens.json + LEXONLY fixture captured on unchanged code; hybrid.py is no longer changed, so the vector_led-vs-retrieve equivalence test is unnecessary; a trace-based no-fetch scenario and a top_k count scenario are added

- [x] **BLOCKER** Goal 3's "same worker thread" check can't tell one hop from two. `asyncio.to_thread` reuses an idle default-executor worker. A two-hop version, for example `to_thread(count_chunks)`, then `to_thread(retrieve)`, then `to_thread(close)`, will usually run every hop on the same thread and pass. — Broken impl that passes: keep the two hops and move `close()` into a third `to_thread`. Thread identity matches and close is called once, but the cancellation hazard Decision 2 removes is still there. — Scenario to add: `test_reader_lifecycle_runs_inside_one_recall_work_call`. Wrap `recall_module._recall_work` so it sets a `threading.local` flag for its duration, and have patched `count_chunks`, `retrieve_vector_led` and `close` assert the flag is set. Alternatively, spy on `recall_module.asyncio.to_thread` and assert the callables passed are exactly `[_check_project, _recall_work, _append_log]` with a project filter, and `[_recall_work, _append_log]` without one. — resolved: adopted the to_thread spy — callables must be exactly [_check_project, _recall_work, _append_log] or [_recall_work, _append_log]

- [x] **BLOCKER** Goal 12's "warns in pytest and does not fail" scenario can't run as written. The live-vault test reads `Settings()` and skips when there is no vault. You can't inject "a corpus note containing a null query's must_not_appear term" without contaminating Brent's real vault, and CI always skips. — Broken impl that passes: the live test still calls the old combined validator and raises. It's skipped everywhere except Brent's machine, so the suite stays green until the day it breaks `make check`, which is the bug Goal 12 exists to fix. — Scenario to add: move the live test's body into a helper such as `check_live_dataset(dataset, vault_path)`. Test it on a `write_vault` tmp vault in three cases: (a) a contaminated null gives `pytest.warns(RecallDatasetDriftWarning, match="null contamination")` and no exception; (b) a missing `expected` file warns too, per Decision 4's "expected-file checks", and does not assert; (c) a clean corpus gives no `RecallDatasetDriftWarning` (`recwarn` empty), so "always warn" fails. — resolved: check_live_dataset(dataset, vault_path) helper, tested on tmp vaults: contamination warns, missing expected file warns, clean vault gives no warning

- [x] **SHOULD** Existing tests will either break or quietly stop testing anything once recall calls `retrieve_vector_led`. The `spies` fixture wraps `recall_module._retrieve`. If that wrapper is removed or no longer called, `retrieve.assert_not_called()` passes vacuously in `test_non_local_embedder_is_refused`, `test_unknown_project_slug_short_circuits_with_a_warning` and `test_empty_witt_index_returns_no_hits_cleanly`. The last one has no other guard. `test_vector_window_covers_every_witt_chunk_up_to_500` and `test_snippets_truncated_on_a_word_boundary` mock `.retrieve.return_value`. A MagicMock unpacked as a tuple raises, so these become 503s. `test_out_of_scope_candidates_dropped_even_if_a_store_misbehaves` overrides `retrieve`. — Broken impl that passes: any. The empty-index test keeps passing even if retrieval runs. — The spec's Files row should list these tests for migration to `retrieve_vector_led` (returning `([...], 0)`), with assertions kept at least as strong. The spy must target the call that actually runs. — resolved: _retrieve is unchanged, so the existing spies and retrieve mocks stay meaningful; Files note lists the extended tests

- [x] **SHOULD** Decision 2's main claim, "a cancelled request can't close the connection under a running thread", has no scenario. — Broken impl that passes: `_recall_work` does its work in the thread, but the handler still has `finally: reader.close()` on the event loop. That passes "closed exactly once" only if close is idempotent-counted, and the thread scenarios are weak (see blocker 2). — Scenario to add: `test_cancelled_recall_does_not_close_reader_under_running_thread`. `retrieve_vector_led` blocks on a `threading.Event`. Cancel the client task through `httpx.ASGITransport`. Assert `close()` has not been called while the event is unset. Then set the event and assert `close()` was called once, from a non-loop thread. — resolved: cancellation scenario added (ASGITransport cancel, close only after the event is set, from a non-loop thread)

- [x] **SHOULD** "The reader is closed" only covers a `retrieve_vector_led` failure. — Broken impl that passes: `_recall_work` closes in `finally` only around the retrieve call, so a `count_chunks` failure or the `count == 0` early return leaks the connection. — Scenario to add: parametrize `test_reader_closed_exactly_once` over {count_chunks raises OperationalError → 503, count == 0 → 200 no-Witt notice, success, retrieve raises}. Assert `close` call_count == 1 and the log line status. Keep `test_missing_lexical_db_is_an_empty_index_not_a_503` and its `not missing.exists()` assert. — resolved: scenario outline over success, count_chunks raises, empty index and retrieve raises; missing-lexical.db scenario kept

- [x] **SHOULD** The `dropped_keyword_only` semantics relative to `top_k` aren't pinned. Is the skipped count taken over every fused lexical-only id, or only those that would have survived the `top_k` slice? And is `top_k` applied after removing lexical-only ids? Recall passes `k_vec + K_LEX`, so the two readings match today, but they diverge on the first resize. — Broken impl that passes: either reading. — Add a sentence to Decision 1, plus `test_vector_led_counts_skipped_before_top_k_slice` with `top_k=2` over 3 vector hits and 3 lexical-only ids. Assert exactly 2 candidates and the pinned count. — resolved: count pinned before the top_k slice; top_k=2 scenario

- [x] **SHOULD** The Goal 6 scenario is ambiguous, and the obvious way to write it hangs. "app.state.warmup_task is cancelled" doesn't say whether that means `cancel()` was called or `task.cancelled() is True`. If the stub blocks a `threading.Event` inside `to_thread`, the worker thread outlives the task and pytest-asyncio's executor shutdown waits on it. — Broken impl that passes: calling `task.cancel()` without awaiting it. Right after lifespan exit, a `cancel()`-was-called check still passes. — Scenario: the stub's `embed_single` does `release.wait(5)`. After `async with ctx` exits, assert `app.state.warmup_task.cancelled() is True` and that nothing was logged at WARNING. Call `release.set()` in a `finally`. Add `test_finished_warmup_is_not_cancelled_at_shutdown`: await the task inside the ctx, then assert `task.cancelled() is False` and `task.exception() is None`. — resolved: asserts task.cancelled() is True, event released in finally, plus a finished-warmup-not-cancelled scenario

- [x] **SHOULD** The `validate_dataset` signature change leaves `test_validation_exemptions_and_scoping` testing nothing. Its three rows (identifier verbatim, short verbatim, null term only in 10_Notes) exercise corpus rules. If `validate_dataset` keeps an ignored `corpus` arg, or the call is changed to `validate_dataset(dataset)`, they pass with no rule exercised. — Broken impl that passes: `corpus_problems` that never exempts identifier/short kinds, or that scans 10_Notes. — Point those rows at `assert ev.corpus_problems(dataset, corpus) == []`. Add `test_corpus_problems_returns_exact_reasons`: both contaminations give `["verbatim query", "null contamination"]` in that order, and a clean corpus gives `[]`. — resolved: exemption rows point at corpus_problems; exact-reasons scenario added

- [x] **SHOULD** The Goal 8 scenarios call `base_url()` directly, but the contract being protected is `recall()` "Never raises". — Broken impl that passes: `base_url` is cached, but `recall()` swallows the first failure badly, or the cached failure path returns a stale URL. — Scenario: invalid env (`SECONDBRAIN_PORT=abc`, which gives a real pydantic `ValidationError` without hand-building one). The first `recall()` returns `{"ok": False, "error": "invalid secondbrain settings: ValidationError"}`. Fix the env; the second `recall()` returns `ok: True` from a MockTransport, and `Settings` was constructed twice in total. Then a third call constructs nothing. — resolved: Goal 8 (base_url cache) cut at triage; no scenarios needed

- [x] **NIT** Goal 4: add a multibyte row to the existing `test_invalid_requests_rejected_with_specific_messages` / `test_boundary_values_are_accepted` tables: `"Witt/" + "é"*507` is accepted, `*508` is rejected. Add an MCP row too, since `RecallFilters` is shared: the tool returns `invalid arguments: ... at most 512 characters`. — resolved: multibyte rows, prefix-wins rule and an MCP row added

- [x] **NIT** Goal 7: the "unchanged until release" scenario also needs to assert `_reconnect` then completes, with `thread.join(timeout=2)` and `not alive`, and that `_collection is None`.
