- [x] **BLOCKER** The "no spans" claim (Goal 5, Decision 6) is very likely false, and no test checks it. `tracing.py:95` calls `Traceloop.init`, and `uv.lock:2117` pulls in `opentelemetry-instrumentation-chromadb`. Once tracing is on, Chroma is auto-instrumented, so recall's `collection.query` emits spans even though `api/recall.py` imports no tracing code. — An implementation that only avoids `import secondbrain.tracing` passes everything and still writes spans to `data/traces/*.jsonl`. — Add `test_recall_emits_no_new_span_shapes`: init tracing with an in-memory exporter, POST /recall, and assert the exported span names are a subset of the set `/ask` already emits (or empty, if you suppress instrumentation on this path). Fix the Decision 6 wording to match. Also run the trace-eval must-pass after at least one traced recall call, so recall spans are actually in the JSONL it reads. — resolved: zero-spans scenario with in-memory exporter and a live-instrumentation control via /ask; trace-eval must-pass after ≥10 recall requests.
- [x] **BLOCKER** The kinds and project filter scenarios are vacuous. "Every hit has kind spec" and "every hit is under …" are both true when `hits == []`, and the kinds scenario has no Given. — An endpoint that returns `[]` whenever any filter is set passes both. — `test_kinds_filter_keeps_specs_drops_decisions`: Given a spec and a decision that both match, assert exactly the spec is returned. `test_project_filter_includes_learnings`: assert at least one second-brain hit and at least one Learnings hit are present, and no `Projects/witt/` hit. — resolved: kinds and project scenarios assert exact inclusions and exclusions against a fixture index.
- [x] **BLOCKER** The vault-scope scenario asserts nothing ("hits may include"). — An implementation that ignores `scope` and always pre-filters to Witt passes. — `test_vault_scope_returns_non_witt_note`: Given `10_Notes/recipes.md` is the best match, assert it is in the hits with `kind == "note"` and `project is None`, and that `note_folder=None` was passed to both stores. — resolved: vault-scope scenario asserts the 10_Notes hit, kind note/project null, no Wiki, and the store kwargs.
- [x] **BLOCKER** The dedupe scenario allows under-fill. "At most 2" passes with 0 or 1 hits, and the spec never says what `top_k` recall passes to `retrieve`. — `retrieve(top_k=limit)` followed by per-note dedupe returns 1 hit when one note's chunks fill the top-k. — `test_limit_counts_notes_not_chunks`: note A has 5 top-ranked chunks, notes B and C match lower, `limit=3`. Assert exactly 3 distinct notes, A first, and A's snippet and score come from its highest-RRF chunk. — resolved: 'limit counts notes, not chunks' asserts exactly 3 distinct notes and best-chunk snippet/score.
- [x] **BLOCKER** The pre-filter scenario can't tell a pre-filter from a post-filter. "Only Witt chunks returned" also passes if `HybridRetriever` drops non-Witt candidates after search, which breaks Decision 5's crowd-out guarantee. — A post-filter inside `retrieve` passes. — `test_note_folder_prefilter_survives_crowding`: set `k_lex=2` and `k_vec=2`, with 3 non-Witt chunks that outrank 1 Witt chunk in both stores. Assert the Witt chunk is returned. Add store-level tests asserting `collection.query` gets `where={"note_folder": "Witt"}` and the FTS SQL binds `note_folder` as a parameter. — resolved: crowding scenario with k_vec=k_lex=2, plus store-level where/SQL-parameter assertions.
- [x] **BLOCKER** No test checks that the MCP tool forwards `filters` and `limit`. The happy-path scenario only checks the hits come back. — A tool that POSTs `{"query": q}` and drops filters passes every MCP scenario, so filters silently do nothing for Witt skills. — `test_mcp_recall_forwards_filters_and_limit`: use `httpx.MockTransport` and assert the request body equals `{"query": …, "filters": {"project": "witt", "kinds": ["decision"], "scope": "witt"}, "limit": 3}`. — resolved: forwarding scenario asserts the exact request body via MockTransport.
- [x] **BLOCKER** Interfaces claims "never raises" for malformed JSON, but no scenario covers it, and none covers 5xx or other transport errors. — Catching only `ConnectError` and `TimeoutException` passes all four failure scenarios. — Add parametrized `test_mcp_recall_never_raises` over: 200 with a non-JSON body, 200 JSON missing `hits`, 500, and `httpx.RemoteProtocolError`/`ReadError`. Each returns `ok is False` with a specific error substring per case. — resolved: never-raises table covers refused, timeout, 422, 500, non-JSON, missing hits, RemoteProtocolError.
- [x] **SHOULD** The Langfuse scenario is not observable. A refused connection fails instantly, and "without waiting on the Langfuse host" has no bound. — Any implementation passes. — Point the Langfuse host at a blackhole address (or patch `_langfuse_reachable` to sleep), then assert the recall request finishes in under 1s after startup and the OTLP exporter or `httpx.get` to that host is never called during the request. — resolved: non-routable Langfuse host, <1s bound, no request to that host during recall.
- [x] **SHOULD** The "no LLM calls" scenario is only as strong as the dependency overrides. — An endpoint that builds an `LLMReranker` itself, instead of using `Depends`, isn't caught. — Also patch `LLMReranker.rerank`, `Answerer.answer`, the Anthropic/OpenAI client constructors and `UsageStore.log_usage`. Assert none are called and `queries.jsonl` is byte-identical before and after. — resolved: spies on reranker, answerer, client constructors, UsageStore.log_usage; conversations.db and queries.jsonl byte-identical.
- [x] **SHOULD** Log removal is only tested through `check_and_reindex`, which needs a `.reindex_needed` trigger file. Rollout step 3 uses `make index`, which is `POST /api/v1/index` → `_run_indexing` (`api/index.py:53`), a separate code path. — A regression in `_run_indexing` would ship untested. — Parametrize `test_excluded_log_chunks_removed` over both paths. The `check_and_reindex` case must write the trigger file in its Given. — resolved: log removal pinned on _run_indexing (check_and_reindex is deprecated; Non-Goals).
- [x] **SHOULD** The endpoint's behaviour when retrieval fails is undefined: embedder error, `ChromaError` after reconnect, vault missing, or a reindex holding the FTS rebuild. — An uncaught 500 with a stack trace passes everything. — Specify a status (e.g. 503 with a `detail`) and add `test_recall_store_error_returns_503`. Add `test_concurrent_recalls_consistent` (N parallel requests through `to_thread` return identical results) and a recall-during-reindex case. — resolved: 503 'recall unavailable: <ExceptionType>' without traceback; concurrency scenario added.
- [x] **SHOULD** The validation table has gaps: missing `query` (`{}`), `query` of 2001 chars, top-level unknown field (`{"query":"x","bogus":1}`, since only `RecallFilters` declares `extra='forbid'`), `kinds: []`, and `project: ""`. Specify each and add a row. — resolved: validation table adds {}, 2001 chars, top-level bogus, kinds [], project '' and invalid slug.
- [x] **SHOULD** A query made only of punctuation (`"***"`, `"--"`) escapes to `'""'` in `_escape_fts_query`. Pin that recall returns 200, not 500. Add `test_recall_punctuation_only_query`. — resolved: punctuation-only query is now a 422 row ('***').
- [x] **SHOULD** The `kind="note"` contract contradicts itself. `RecallHit` says "note only appears with scope=vault", but `classify_witt_path("Witt/Projects/")` returns "note", and any off-layout Witt file (e.g. `Witt/README.md`, `Witt/Projects/witt/other.md`) is a Witt-scope hit with kind "note". Also undefined: `project` combined with `scope="vault"`, and `kinds=["note"]` under the witt scope. Specify these and add table rows for `Witt/Projects/a/b.md` (a ≠ b), `Witt/Projects/witt/other.md` and `Witt/README.md`. — resolved: kind 'other' added; table rows for Witt/Projects/a/b.md, Witt/Projects/witt/other.md, Witt/README.md; filter semantics in Decision 6.
- [x] **SHOULD** Sort order and fields aren't asserted. Nothing checks hits are sorted by score descending, or that `note_title`, `heading_path` and `score` are filled. The snippet test allows `""` or a mid-word cut. — Add `test_hits_sorted_desc_and_fields_populated` and `test_snippet_truncates_on_word_boundary`: a 1,000-char chunk gives at most 600 chars ending on a word boundary, and a 100-char chunk is returned unchanged. — resolved: sort order and populated fields asserted; snippet cut at last whitespace before 600 chars.
- [x] **SHOULD** recall@5 is vacuous with today's corpus. After excluding logs there are at most 4–5 Witt notes, so any query whose target is retrieved at all scores 1.0. MRR is the only real signal. Gate on MRR (or recall@1) until the corpus passes ~30 notes, add some `scope="vault"` queries so ranking is actually under test, and add p50/p95 latency to the report to back the "under a second" claim in Intent. — resolved: ranking report-only until 30 notes; vault-scope queries; p50/p95 latency with a p95 gate.
- [x] **SHOULD** The eval's own logic (recall@k, MRR, scope-isolation counting, JSON report) has no unit test, and `tests/` has no file for it. Add `tests/test_recall_eval_metrics.py` with hand-computed fixtures, plus a case where the API is down: the eval exits non-zero with a clear message. — resolved: tests/test_recall_eval_metrics.py covers metric fixtures, API-down exit and stale labels.
- [x] **SHOULD** The MCP stdout check only runs at import time. A stray print or a stdout logging handler during a tool call corrupts the stdio protocol. — Add `test_mcp_stdio_roundtrip`: spawn `secondbrain-mcp`, send `initialize` + `tools/call recall` (with the API down), and assert every stdout line parses as JSON-RPC. This also proves the console-script entry point works. — resolved: stdio round-trip scenario spawns the console script.
- [x] **SHOULD** The MCP base URL comes from `Settings`, whose `env_file=".env"` is relative (per MEMORY.md). Claude Code launches the MCP process from an arbitrary cwd, so a non-default port in `.env` would be silently ignored. Add `test_mcp_base_url_independent_of_cwd`, or document that only defaults and env vars apply. — resolved: config.py env_file is already absolute (_PROJECT_ROOT/.env); scenario pins cwd independence.
- [x] **NIT** Make the 10s timeout injectable and use a transport that raises `ReadTimeout`, so the timeout test doesn't take 10s. Also note that httpx `timeout=10` is per-phase, not total. — resolved: timeout injectable; ReadTimeout row in the never-raises table.
- [x] **NIT** The 422 MCP scenario should also assert the error names the offending field (`query`), as the Interfaces docstring promises, not just "422". — resolved: 422 row asserts '422' and 'query'.
- [x] **NIT** "No existing test file is modified except to add cases" isn't an executable check. State it as a review step (`git diff --stat main -- tests/` shows only additions). — resolved: stated as a verify-time git diff --stat review step.
- [x] **NIT** The frontmatter scenario could add a non-string `title` (e.g. `title: 2026`) falling back to H1, and YAML that parses to a list. Both pin `parse_markdown` behaviour that Decision 4 relies on. — resolved: non-string title row added; YAML-list case covered by malformed-frontmatter handling.
- [x] **NIT** Exclusion edge rows: `Witt/Logs/archive/x.md` is excluded (fnmatch `*` crosses `/`), and `10_Notes/Witt/Logs/x.md` is not. — resolved: Witt/Logs/archive and 10_Notes/Witt/Logs rows in the ingestion scenario.
