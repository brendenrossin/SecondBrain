## Tester review — 004 (r2)
Verdict: approve with changes

Coverage: 13 goals, 42 scenarios, uncovered goals: none. Goal 4 (`k_vec`) and Goal 8 (`client`) are only partly covered, and one Goal 13 row passes on broken code.

- [x] **BLOCKER** The Goal 4 outline asserts `k_vec == 30`, but with a 7-chunk fixture `k_vec_for(7) == k_vec_for(0) == 30`. So that assertion can't fail. — A broken implementation passes: one that never records the count, or one that logs a holder's default `k_vec` without updating it after counting. — Add a row that patches `_VectorLedReader.count_chunks` to return 120 (like `test_vector_window_covers_every_witt_chunk_up_to_500`), then injects the embedder failure, and asserts the 503 log line has `witt_chunk_count == 120 and k_vec == 120`. Test: `test_503_after_counting_logs_real_count_and_window[count120-embedder]`. — resolved: count=120 scenario asserts witt_chunk_count 120 and k_vec 120 on the 503 line
- [x] **BLOCKER** "Whitespace exactly at index 600 cuts at 600" is vacuous. If 600 is the only whitespace, a scan starting at 599 finds nothing and falls back to `text[:600]`, which gives the same output. — A broken implementation passes: `range(SNIPPET_MAX - 1, 0, -1)` (an off-by-one at the boundary, which is the bug this row exists to catch). — Put whitespace at index 600 **and** at index 300, and assert the snippet is `text[:600]`; the broken scan returns `text[:300]`. New row in `test_snippets_truncated_on_a_word_boundary`. — resolved: whitespace at 300 and 600; expects text[:600]
- [x] **BLOCKER** Decision 4 says `check_live_dataset` "never raises", and nothing proves it. Every scenario uses a well-formed temporary vault. — A broken implementation passes: one that calls `witt_corpus(vault_path)` and lets errors propagate (missing vault dir, no `Witt/` folder, a note that can't be read). — Add `test_check_live_dataset_never_raises` with a `vault_path` that doesn't exist and a vault with no `Witt/` folder. Assert it returns a list without raising, and pin what it returns in each case (for example, every labelled query reported as `expected file missing: ...`). — resolved: never-raises outline (missing vault_path, no Witt/) pins one missing-file entry per labelled query
- [x] **SHOULD** Goal 7 will break existing tests, and the spec doesn't say so. `test_warmup_failure_is_logged_not_raised` reads `app.state.warmup_task.exception()` *after* the lifespan exits, which becomes `None.exception()`. Decision 5 also doesn't say whether `warmup_task = None` is set when warmup is disabled. If it is, `test_warmup_off_by_default` and `test_warmup_skipped_for_non_local_embedder` (`not hasattr(app.state, "warmup_task")`) fail too. — Without this pinned, the likely "fix" is to delete the `hasattr` assertions, which weakens them. — State that the attribute is cleared only when it exists. Have "Shutdown with warmup disabled is a no-op" assert `not hasattr(app.state, "warmup_task")`. List the edit to the failure test in Files: capture the task inside the context; keep the assertion. — resolved: attribute cleared only when it exists; disabled-warmup asserts no attribute; failure test captures the task inside the lifespan (Files)
- [x] **SHOULD** Goal 8 says the `client` and `collection` properties never return `None`. Only `.collection` is stress-tested, and the stress test is probabilistic by the spec's own admission. Nothing deterministic proves the read-into-a-local fix. — A broken implementation passes: one that fixes `collection` and leaves `client` as `if self._client is None: ...; return self._client`. So does any version that still re-reads the attribute after the check, if the race window is never hit. — Add `test_collection_and_client_read_the_attribute_once`. Use a `VectorStore` subclass whose `__getattribute__` returns the real object on the first read of `_collection` / `_client` and `None` on the next one. Assert that both properties return a non-None object. Also add `.client` readers to the stress scenario. — resolved: read-once outline for both properties; .client readers added to the smoke test
- [x] **SHOULD** The Goal 9 table uses `"[]"` as the non-object body, and `[]` is falsy. — A broken implementation passes: `if not payload: raise ApiFailure(...)`. — Replace or add a truthy non-dict row, `[{}]` or `"\"str\""`. Note that `Harness.run` currently always sends `httpx.Response(200, json=...)`, so the harness needs a raw-content responder; list that in Files. — resolved: [{}] and a JSON string rows added; Harness gets a raw-content responder (Files)
- [x] **SHOULD** Decision 3 says "if `fdopen` raises, the fd is closed first", and no scenario covers it. — A broken implementation passes: one that leaks the fd. — Add `test_recall_log_fdopen_failure_closes_fd`: patch `recall_module.os.fdopen` to raise `OSError` and spy on `os.close`. Assert a 200, a WARNING containing "recall_log write failed", and that `os.close` was called once with the fd `os.open` returned. — resolved: fdopen-failure scenario asserts os.close with the opened fd
- [x] **SHOULD** Risks says "a test pins that it is never `LexicalStore`'s cached instance", but there is no such scenario in the Acceptance Criteria. — A broken implementation passes: a refactor that caches `_VectorLedReader` or returns it from `get_lexical_store`, which makes `/ask` see "chunk not found" everywhere. Nothing would catch it. — Add `test_vector_led_reader_is_never_the_shared_store`. After a recall, `deps.get_lexical_store()` is a plain `LexicalStore` (`type(...) is LexicalStore`) and its `get_chunk(<known id>)` returns the row. Also assert `_VectorLedReader` is constructed once per request, by spying on `__init__` across two requests. — resolved: never-the-shared-store scenario (type is LexicalStore, get_chunk returns the row, two constructions for two requests)
- [x] **SHOULD** `check_live_dataset` "issues one warning per problem" and "returns corpus_problems plus `expected file missing: <path>`". The scenarios only assert that a matching warning exists. — A broken implementation passes: one that emits a single joined warning, or returns `[]` while still warning. — Use a vault with both null contamination and one missing expected file. Assert the return value equals `["null contamination", "expected file missing: Witt/..."]` exactly, with 2 `RecallDatasetDriftWarning`s, in that order. — resolved: exact return list and 2 ordered warnings scenario
- [x] **SHOULD** Renaming `_ReadOnlyLexicalStore` breaks direct references in `tests/test_recall_api.py`: the import on line 13, `_inject` (`fts`/`count`), `test_vector_window_covers_every_witt_chunk_up_to_500` and `test_recall_reads_lexical_db_through_its_own_read_only_connection`. The Files row only says the `spies`/`HybridRetriever` patches stay valid. — List the renames. Require that the read-only test keeps its `OperationalError, match="readonly"` assertion against `_VectorLedReader`. — resolved: renames listed in Files; read-only assert kept
- [x] **NIT** The "finished warmup is not cancelled" scenario can't tell a done-check from an unconditional `task.cancel()`, because `cancel()` on a done task is a no-op. Optionally spy on `task.cancel` and assert it was not called. — resolved: task.cancel spied and not called on a finished warmup
- [x] **NIT** The close-once outline should add a row for the unknown project: no `_VectorLedReader` is constructed and `close` is called 0 times. That pins "the guard comes before any connection is opened" on the step-3 short-circuit too. It should also add the missing-`lexical.db` row with the same 0-close expectation. — resolved: zero-construction outline for unknown project and missing lexical.db
- [x] **NIT** The cancelled-request scenario doesn't say whether a cancelled request writes a log line. `CancelledError` isn't caught by `except Exception`, so today it writes none. Pin "no log line". Set the event in a `finally`, and give "close is called exactly once" a bounded wait (for example, poll for 2 s). — resolved: cancelled request pins no log line, event set in finally, close within 2 s
- [x] **NIT** For the `é` rows, write `"é"` explicitly so an NFD-encoded source file can't turn one character into two. For the umask scenario, mark it as not safe to run in parallel with other tests (`os.umask` is process-global). — resolved: é written as \u00e9; umask test marked not parallel-safe
- [x] **NIT** "The private reader still serves count and search" should assert the exact 4 chunk ids from `search`, not just the count. "The eval error names every reason" should also assert structural reasons come before corpus reasons ("keeps today's order"). — resolved: exact 4 chunk ids; structural-before-corpus order asserted
