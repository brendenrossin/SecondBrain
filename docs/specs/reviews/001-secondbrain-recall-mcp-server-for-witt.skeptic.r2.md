## Skeptic review — 001 SecondBrain recall MCP server for Witt (v0.2.0, round 2)
Verdict: approve with changes

Unstated assumptions:
1. Tracing is on in production `.env` (`SECONDBRAIN_TRACING_ENABLED=true`). If it is off, Goal 6 doesn't matter in prod, and the trace-eval Given ("API runs with tracing enabled") isn't the live state. — Not written down.
2. With tracing on, LLM traces from `/ask` traffic already exist in `data/traces/`, so `test_sample_has_llm_traces` can pass with "0 skipped". Recall adds no spans, so recall traffic can't help it pass. — Not written down.
3. Witt project slugs are always lowercase kebab-case. The `project` pattern `^[a-z0-9][a-z0-9-]*$` rejects any slug with `_` or `.`. — Not written down, and not cited from Witt's Data contract.
4. The vault-wide null topic examples ("sourdough recipe") have no match outside `Witt/`. They do: the vault has recipe notes. So the null set only works at `scope="witt"`. — Not written down; Evals never says which scope null queries run at.
5. `HybridRetriever.min_similarity=0.3` (`retrieval/hybrid.py:38`, built by `get_retriever` with defaults) still applies under the new floor. "Floor disabled" calibration therefore never sees vector similarities below 0.3, and any calibrated floor below 0.3 does nothing. — Not written down.
6. `RecallKind` can live in `vault/witt.py` and be imported by `models.py` without an import cycle. It can't as written (see SHOULD below). — Not written down.
7. Brent installs `etc/newsyslog.d/secondbrain.conf` into `/etc/newsyslog.d/` by hand (it needs sudo). Editing the repo copy rotates nothing. — Not in Rollout.

- [x] **BLOCKER** The unknown-slug scenario contradicts Decision 6's filter semantics. Decision 6 says `project` keeps `Witt/Projects/{project}/**` **plus all `Witt/Learnings/**` in either scope**. The Background says every fixture note matches the query, the floor is 0.0, and the fixture includes `Witt/Learnings/pin-the-docstring.md`. So `{"project": "secondbrain"}` returns the Learning by design, yet the scenario asserts `hits []`. One engineer short-circuits unknown slugs to `[]`; another returns Learnings plus a warning. The second is also misleading: an agent that typos the slug gets cross-project Learnings and may read them as project-specific prior art. — Fix: state the rule in Decision 6, e.g. "if `project` names no directory under `Witt/Projects/`, return `hits: []` plus the warning (Learnings are not returned)", and keep the scenario. Or keep Learnings and change the scenario to assert exactly the Learning plus the warning. — resolved: unknown slug short-circuits to [] + warning, no Learnings; Decision 6 step 2 states the rule.
- [x] **BLOCKER** The null-query hard gate can't fail. Calibration sets `recall_min_similarity` to the midpoint above the highest null top-hit similarity, measured on the same ≥4 null queries the gate then runs ("0 of ≥4 null queries return any hit"). The gate passes whenever calibration succeeds. Intent property #1 ("an empty result reliably means nothing relevant") is the reason the floor exists, and nothing verifies it out of sample. — Fix: split the null set into calibration and held-out halves (≥4 each) and gate only on the held-out half. Calibrate on the **expected** note's similarity, not the labelled query's top-hit similarity (the top hit can be the wrong note). Make "recalibrate" fire on corpus growth too, not only embedder changes; the 30-note MRR trigger is a natural point, because more notes means a higher max null similarity. — resolved: held-out split for gates; calibration on the expected note's similarity; recalibration every +10 notes.
- [x] **SHOULD** The eval is contaminated by this spec's own vault mirror. `Witt/Projects/second-brain/specs/001-secondbrain-recall-mcp-server-for-witt.md` is indexed (v0.2.0, `scope="witt"`). Lines 339–340 name the null topics "Kubernetes ingress TLS, a sourdough recipe", so any paraphrased null query on those topics hits this spec through BM25 and vectors. That pushes calibration into the "ranges overlap, stop" branch, or produces a null false positive. The rule "not verbatim in any indexed note" doesn't help, because paraphrases still match semantically. The same mirror quotes every fixture path (`ADR-001-overrides.md`, etc.), so it will also rank high for ADR-001-shaped labelled queries. — Fix: remove the example null topics from the spec, and require null topics that appear nowhere in the vault, checked with a grep of the vault at eval time. Either exclude the spec under test from labelled results or list it as an acceptable co-hit. — resolved: the spec names no example null topics; must_not_appear terms are grepped across the vault (null_contamination gate); allowed_cohits for the spec mirror.
- [x] **SHOULD** The floor quietly turns hybrid into vector-gated retrieval, and the spec doesn't say so. Step 3 drops BM25-only candidates (similarity 0), and anything under the retriever's 0.3 store floor also lands at 0. Exact-identifier queries ("ADR-002", "suppress_instrumentation", "check_and_reindex") are BM25's strength, and they return `[]` whenever bge-base scores them below the floor. The agent then reads "no prior art". — Fix: state in Decision 6 that BM25 only reorders and never admits a hit. Add ≥2 identifier-style labelled queries to the dataset so the eval measures this. Or allow a BM25-only rescue above a rank or score threshold, if Brent prefers. — resolved: Brent chose real-similarity rescoring of keyword-only candidates; identifier queries in the eval.
- [x] **SHOULD** Import cycle in Interfaces. `models.py` imports `RecallKind` from `secondbrain.vault.witt`. Importing `secondbrain.vault.*` runs `vault/__init__.py`, which imports `connector.py`, which does `from secondbrain.models import Note` while `models` is only partly initialised. The result is an ImportError at API start, or one that depends on import order. `connector.py` also imports `witt.py` for `WITT_LOG_EXCLUDE`. — Fix: define `RecallKind` in `models.py` and have `witt.py` import it from there, or put `witt.py` outside the `vault` package. — resolved: RecallKind lives in models.py.
- [x] **SHOULD** `scope="vault"` has no named consumer and isn't calibrated. The Intent and Non-Goals point at `spec-draft`/`close` asking about prior Witt work. Nothing names a caller for whole-vault recall. Vault scope still brings the Wiki exclude, the `note` kind, a 422 rule, ≥4 eval queries, prompt-injection exposure, and a floor calibrated only on Witt-scope nulls. That makes "empty means nothing relevant" unproven for vault scope. — Fix: either cut it to v2 (smaller spec, smaller attack surface), or add vault-scope null queries to calibration and the held-out gate, and name the consumer. — resolved: Brent cut scope='vault' to v2 (Non-Goals).
- [x] **NIT** Validation row `{"filters": {"kinds": ["note"]}}` expects the detail to name `kinds`. A Pydantic `model_validator` error carries `loc=("body","filters")`, and the pinned message says "kind 'note'…", which doesn't contain "kinds". — Fix: make the message start "kinds: kind 'note' requires scope 'vault'", or raise from a field validator on `kinds` that reads `scope` via `info.data`. — resolved: moot, since kinds 'note' was removed; validation table pins messages.
- [x] **NIT** Writing `recall_log.jsonl`: concurrent `to_thread` workers append lines that can exceed 4 KB (a 2000-char query plus 20 hits), and newsyslog rotates by rename. — Fix: specify open-append-close per request under a `threading.Lock`, and add the `/etc/newsyslog.d` install step to Rollout. — resolved: open-append-close under a threading.Lock (Decision 8); newsyslog install step in Rollout 7.
- [x] **NIT** Warmup race: a fire-and-forget `to_thread` warmup and the first request can both enter `lru_cache`d `get_embedder()` at once. `lru_cache` doesn't serialise construction, so bge-base can load twice. The spec also doesn't say a reference to the task is kept. — Fix: call `get_embedder()` once on the event loop before spawning the thread, and keep the task on `app.state`. — resolved: get_embedder() is called on the event loop before the thread; task held on app.state; locked lazy load.
- [x] **NIT** "Every labelled query's expected note is in the index" is listed under hard gates but reads as a reporting rule. Say whether a stale label fails the run. — resolved: stale labels fail the run (hard gate).
